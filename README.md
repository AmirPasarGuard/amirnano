# Amir Nano Railway

پنل مدیریتی فارسی و راست‌چین برای Railway با پایگاه داده PostgreSQL. این نسخه بخش‌های Hosts، Nodes، Cores، Groups، Users و Configs را دارد و لینک Subscription خصوصی را از کانفیگ‌هایی که مدیر **دستی** وارد می‌کند ارائه می‌دهد.

> این پروژه به‌تنهایی هستهٔ Xray یا سرویس VPN را اجرا نمی‌کند؛ وضعیت Node و مقدار Usage در این نسخه دستی است. فیلد IP هم به‌تنهایی IP ورودی/خروجی Railway را تعیین نمی‌کند.

## متغیرهای Railway

در سرویس برنامه این متغیرها را تنظیم کن:

- `ADMIN_USERNAME`: نام کاربری مدیر (مثلاً `admin`)
- `ADMIN_PASSWORD`: یک رمز عبور قوی و یکتا
- `SESSION_SECRET`: یک مقدار تصادفی طولانی و محرمانه (حداقل ۳۲ بایت تصادفی)
- `DATABASE_URL`: متغیر ارجاعی به `DATABASE_URL` سرویس PostgreSQL
- `COOKIE_HTTPS_ONLY`: مقدار `true`

**مهم:** `ADMIN_PASSWORD` و `SESSION_SECRET` را داخل GitHub قرار نده و با کسی به اشتراک نگذار.

## استقرار

1. محتوای این پوشه را در ریشهٔ یک مخزن GitHub قرار بده؛ فایل `main.py` باید در ریشه باشد.
2. در Railway از مخزن GitHub یک سرویس بساز.
3. یک سرویس PostgreSQL به همان پروژه اضافه کن.
4. متغیرهای بالا را در Variables سرویس برنامه وارد کن.
5. برای سرویس برنامه از Settings → Networking یک دامنهٔ عمومی بساز.
6. بعد از Online شدن سرویس، آدرس `/login` را باز کن و وارد شو.

`railway.json` فرمان اجرا و مسیر Health Check را تنظیم می‌کند؛ برنامه روی `0.0.0.0:$PORT` گوش می‌دهد.

## شروع کار

1. از بخش Groups یک گروه بساز.
2. از Hosts و Nodes اطلاعات زیرساختت را وارد کن.
3. از Users کاربر بساز و گروه را انتخاب کن؛ Usage را فعلاً دستی وارد کن.
4. از Configs فقط متن کانفیگ‌های موجود و مجاز خودت را ثبت کن و آن‌ها را به همان گروه وصل کن.
5. از Users لینک Subscription خصوصی همان کاربر را کپی کن.

لینک Subscription مثل رمز است: هرکس آن را داشته باشد، می‌تواند محتوای همان Subscription را بخواند. اگر لینک افشا شد، آن را از دیتابیس باطل/تعویض کن.

## محدودیت‌های نسخه

- Usage به‌صورت دستی وارد می‌شود؛ محاسبهٔ واقعی ترافیک ندارد.
- وضعیت Node دستی است و اتصال زنده به Core انجام نمی‌شود.
- کانفیگ ساخته یا اعتبارسنجی نمی‌شود؛ متن واردشده فقط منتشر می‌شود.
- تغییرات ساختار دیتابیس به‌صورت خودکار migration نمی‌شوند؛ قبل از تغییر مدل‌ها از دیتابیس پشتیبان بگیر.
